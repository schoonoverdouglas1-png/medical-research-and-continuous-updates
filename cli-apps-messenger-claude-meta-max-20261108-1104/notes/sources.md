## Self-interface / agent-to-agent (general, legitimate)
- MCP spec https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio — stdio: client launches server as subprocess, JSON-RPC over stdin/stdout; also Streamable HTTP. MCP = agent→tools/data (vertical).
- A2A https://a2a-protocol.org/llms.txt + site — Agent2Agent v1.0, Google→Linux Foundation/AAIF, Agent Cards at /.well-known/agent-card.json, Tasks/Messages/Artifacts, official a2a-cli (github.com/a2aproject/a2a-cli) for discovering/messaging A2A agents from terminal. A2A = agent→agent (horizontal), complementary to MCP.
- Muse Code specifics give the literal "talk to itself" answers: (1) session messaging between live sessions (same machine/user, Linux supported); (2) muse serve MSP + SDK to drive a session from your own program; (3) muse exec headless for scripts/CI; (4) subagents/workflows inside one session; (5) MCP client support to call tools/other agents exposed as MCP servers.
- Muse personal specifics: musegadget send-user-msg is the literal "local program → Muse" CLI; reverse direction Muse→machine via system.run/custom commands. An agent ON Ubuntu cannot message a Muse personal agent on another machine except via WhatsApp/muse.ai web (no API) or a paired gadget on that account.
